# Машинные схемы версии 1.1

## Параметры и допуски

Схема реестра: schema_version = '1.1'. Обязательны шесть доменов из registry;
дополнительные домены допустимы при согласованной области. Каждый параметр
имеет author_sessions со всеми соавторами; одной записи author недостаточно
для проверки независимости. bool, NaN и бесконечность не являются числами.

| kind | Поля | Семантика |
|---|---|---|
| absolute | minus, plus: конечные неотрицательные числа | Отклонения от value в единице параметра |
| relative_percent | minus, plus: конечные неотрицательные числа | Проценты от абсолютного ненулевого номинала; больше 100% не запрещено форматом, но требует физического обоснования |
| min_only | min: конечное число | Нижний допустимый предел, не оценка погрешности |
| max_only | max: конечное число | Верхний допустимый предел, не оценка погрешности |
| fit | designation, standard_ref, nominal_ref, limits_refs | Обозначение посадки/поля допуска, стандарт и редакция/таблица, ссылка на номинал и не менее двух ссылок на предельные размеры/отклонения |

nominal_ref и limits_refs используют синтаксис `[PARAMETER_ID@revision]` с
числовой ревизией. Таблицы посадок автоматически не вычисляются: R4/R6 обязаны
проверить размерный интервал, систему отверстия/вала, единицы и редакцию стандарта.
min_only/max_only задают ограничение; фактическое значение может его нарушать.
Валидатор проверяет запись ограничения, а сравнение расчётного результата с ним
выполняется в соответствующем инженерном тесте. Непосредственное сравнение
value и min/max не заменяет такой тест.

## JSON-доказательство расчёта

calculation содержит script, command, expression, code_files, output.
output указывает на JSON-манифест, в том числе для CAD/CAE: бинарные результаты,
решатель, входные файлы и логи перечисляются в artifacts и environment.

Обязательные поля манифеста:

- schema_version: '1.1'; script_sha256 — хэш основного скрипта.
- registry_snapshot — сохранённый YAML реестра; registry_sha256 — SHA256 его байтов.
- inputs и outputs — списки id, revision, engineering_sha256, value, unit.
- code_files — список path, sha256 всех локальных модулей расчёта, включая основной.
- environment — версии Python/библиотек/решателя, настройки и seeds при применимости.
- artifacts — входные таблицы, сетки, decks, результаты и логи с path, sha256.

engineering_sha256 — SHA256 канонического JSON полей revision, value, unit,
tolerance, uncertainty, scope, meaning, provenance, depends_on, calculation.
Алгоритм: repo_support.engineering_sha. Статусы зрелости, review, history,
author и baseline_id исключены: оформление проверки не меняет физический вход.
Изменение этих административных полей проверяется отдельными правилами.

Валидатор сверяет хэш снимка, определения параметров в снимке, текущие
определения, единицы, значения и точный набор зависимостей. Изменение чужого
независимого параметра или добавление review не требует пересчёта всех моделей.
Изменение своего входа, формулы, допуска или кода делает текущий результат
непригодным. Нельзя «исправить хэш» без нового расчёта и доказательства.

STALE сохраняет исторические ревизии/хэши; обычный режим не требует совпадения
устаревшего кода с текущим. Хэш его сохранённого снимка всё равно проверяется.
Строгий режим запрещает любые STALE в активном реестре. Полностью удаляемые
параметры и их акты сначала архивируются; ID не переиспользуются.

## Акты и решения

В cross_check_log.md только YAML-блок с record_type: review является актом.
review_template и простое упоминание ID не считаются доказательством.
Обязательные машинные поля: review_id, reviewer {role, session_id},
author_sessions, independence_basis, reviewed_commit, scope, parameter_refs,
artifacts, checks, verdict, validity. Каждый check содержит method, expected,
observed, reasoning, result. PASS несовместим с FAIL/NOT_RUN.
parameter_refs имеют id, revision, engineering_sha256; artifacts — path, sha256.

VERIFIED/LOCKED требуют точного ID акта, PASS, совпадающей области, проверяющего,
ревизии и полного набора соавторов. Для CURRENT необходим CURRENT-review.
LOCKED дополнительно требует decisions/<baseline_id>.md с record_type: decision,
APPROVED, пустым blocking_issues_remaining, соответствующим параметром,
review_ids, artifacts, полномочиями и временем утверждения. Форма — templates.

--check-git читает сохранённые blobs из reviewed_commit/baseline_commit,
сверяет параметры и хэши файлов. Нужны локальные Git-объекты; CI получает
полную историю. SHA формата commit без этого флага проверяется лишь синтаксически.
Сам файл акта/решения сохраняется после проверенного commit, без самоссылочного SHA.
Хэши, имена сессий и строки approved_by не удостоверяют личность и не являются
криптографической подписью. Реальная независимость и полномочия проверяются
оператором и правилами принятия изменений.

## Markdown и границы проверки

Проверяются ссылки `[ID@числовая_ревизия]` во всех активных Markdown-файлах,
включая блоки кода. Неизвестные ID, устаревшие ревизии и STALE запрещены.
Исключены templates/, examples/, archive/, tests/fixtures/, sources/raw/ и служебные каталоги. Первичные материалы являются данными источника; их синтаксис не обязан совпадать с проектными ссылками.
Исключение не разрешает использовать их как текущую проектную базу.
Архивный документ должен ссылаться на свой commit; при возврате в работу его
копируют в активный раздел и актуализируют. Ссылку на текущий review STALE
не допускается прятать в исключённый каталог ради прохождения CI.

Регулярное выражение проверяет ссылки, но не обнаруживает все числа без ссылок.
Полнота регистрации чисел, физический смысл, размерностный анализ, полнота
интерфейсов COTS, закрытие задач и прохождение ворот остаются предметом review.
PASS пустого PROJECT-реестра подтверждает структуру стартовой заготовки, не G1.

## COTS

drives/cots_catalog.yaml содержит components: отображение ID → запись формы
templates/cots_component.yaml. Численные размеры и номиналы находятся в registry;
каталог содержит ссылки. APPROVED_FOR_LAYOUT требует локальный каталог с хэшем,
страницу/исполнение, систему координат, заполненные required_interfaces,
проверенные проектные параметры, отсутствие unresolved_items и текущий PASS,
покрывающий параметры и исходный каталог. Статус не подтверждает доступность
закупки автоматически; поставку и замены проверяет R3/R6.

## Git и контроль байтов

Начиная с v1.2.1, корневой `.gitattributes` отключает автоматическое
преобразование переводов строк для сохранения байтовых SHA256. Текстовый diff
по-прежнему возможен. Изменение окончания строки меняет хэш; это нормальное
изменение артефакта. Для файлов Git LFS проверка commit сопоставляет hash
объекта из LFS-указателя с ожидаемым SHA256; локально необходим фактический
файл. Прежние Git-commits не переписываются автоматически.
