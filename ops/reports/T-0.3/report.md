# T-0.3 · Раннер задач REV

Раннер читает карточку и политику роли, создаёт или переиспользует рабочее дерево на базе `main` и собирает ResultBundle в `ops/runs/<ID>/<run>/`. При PASS пакет поступает в `ops/review_queue/<ID>.md` с фрагментом диффа до 60 000 байт. После FAIL или ERROR гейта исполнитель получает перечень дефектов на следующий раунд. По исчерпании раундов раннер возвращает BLOCKED. При исчерпании квоты он переключается на следующий профиль роли, а при отсутствии свободных профилей возвращает WAIT с ближайшим временем сброса.

## Изменения второго круга

- Codex получает UTF-8 текст `TASK.md` через stdin с позиционным аргументом `-`. При повторе к тексту добавляется список дефектов. Разбор `tokens_used` поддерживает обычный, неразрывный и узкий неразрывный пробелы. Из сохранённого журнала пробы ГК получено 24 734 токена.
- `ops/backends.yaml` задаёт `REV_PYTHON`, `REV_FREECADCMD` и начало `PATH`. Раннер передаёт эти настройки исполнителю, перечисляет пути в `TASK.md` и использует те же инструменты для гейтов. При отсутствии настроек используются текущий Python и поиск FreeCAD в `PATH`.
- G-SCOPE получает копию `meta.json` в игнорируемом временном каталоге рабочего дерева. Для расчётных гейтов карточка указывает `gate_inputs.params`, для геометрических — `gate_inputs.model` и `gate_inputs.roles`. `gate_inputs.poses` передаётся при наличии. Отсутствующий скрипт или отсутствующие входы карточки дают NOT_AVAILABLE. Выход запущенного гейта с кодом 2 без отчёта даёт ERROR.
- Перед запуском раунда предыдущий `report.md` архивируется в каталоге запуска как `report.previous.md`. Для приёмки раунда требуется новый отчёт. При таймауте Windows Job Object завершает дерево процессов, раннер возвращает TIMEOUT.
- Профили Codex используют одну блокировку `%LOCALAPPDATA%\rev-orch\codex.lock` с PID и временем начала. ОС освобождает блокировку при выходе владельца. При ошибке 1909 раннер возвращает WAIT_SANDBOX с кодом выхода 5 и временем повтора через 660 секунд в UTC. В этот интервал запуск любого профиля возвращает тот же срок ожидания. Повтор той же команды после указанного времени продолжает сохранённый раунд с его дефектами.

## Допущения и источники

Политика ролей, порядок резервных профилей, таймауты и интерфейсы гейтов взяты из TASK.md и уточнений ГК. При `--backend auto` заданный в карточке профиль используется первым. Время сброса квоты без часового пояса трактуется как локальное. Если подходящего времени в сообщении нет, применяется пауза 3 600 секунд. В сухом прогоне используется временное дерево и адаптер echo.

## Проверка и проба ГК

Прогон pytest выполнен на Windows с Python 3.13.17. Сценарии покрывают полный сухой прогон, повтор после G-SCOPE FAIL, свежесть отчёта, контракты трёх CLI гейтов, код 2 без отчёта, перенос UTF-8 промпта размером 120 044 байта через stdin, квоты, таймаут дерева процессов, блокировку между процессами и возобновление того же раунда после 1909.

Живая проба на `bos` до этих изменений завершилась PASS по проверке ГК. На втором круге использованы её сохранённый журнал и тестовые процессы. В этом рабочем дереве внешние гейты отсутствуют, их интерфейсы проверены на заглушках.

Команды для управляющего checkout в PowerShell 7. Последняя команда предназначена для повторной живой пробы ГК после интеграции.

~~~powershell
& 'E:/Tools/Python313/python.exe' -m pytest tests/ops
& 'E:/Tools/Python313/python.exe' ops/run_task.py --probe --dry-run --backend bos
& 'E:/Tools/Python313/python.exe' ops/run_task.py --probe --backend bos
~~~

Флаг `--probe` создаёт карточку `ops/tasks/T-PROBE.yaml` внутри каталога запуска. Для живой приёмки проверить PASS, `backend: bos` в `meta.json` и версию Python в `report.md` пакета.

После интеграции T-0.1 геометрические тесты запускаются отдельно.

~~~powershell
& 'E:/Tools/FreeCAD-1.1/bin/freecadcmd.exe' tests/ops/test_geom_gates.py
~~~
