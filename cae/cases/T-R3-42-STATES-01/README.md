# Аудит 42 нагрузочных состояний REV

## Расчёт по огибающей для каждого состояния

[Индекс расчёта](results/index.json) связывает все 42 ID с отдельными журналами
`S42-001.jsonl`–`S42-042.jsonl`. Первая строка каждого журнала содержит исходные
данные, единицы, систему координат R4, граничные условия, хэши и определяющие
сочетания. Далее идут все сочетания данного состояния. Поле `row` сохраняет
номер сочетания в общей огибающей. [Манифест расчёта](results/manifest.json)
фиксирует допущения, входы, команды и хэши журналов, а также происхождение
[статусов](../../../params/T-R3-42-STATES-01-status.json) и
[осевых усилий на узлах привода](../../../drives/T-R3-42-STATES-01-envelope-demand.json).

Результат `CALCULATED_ASSUMED` относится к утверждённой
[огибающей](../design_boundary_phase_load_envelope/README.md) и её дискретным
статическим сочетаниям. Штатный решатель воспроизвёл 3 456 удерживаемых
сочетаний и 42 отсчёта ZERO. В 174 сочетаниях освобождённого осевого пути при
ненулевой нагрузке зафиксировано `NO_STATIC_EQUILIBRIUM`. Для двух свободных
тел максимальная абсолютная невязка компоненты силы равна 0 Н. Невязка
момента достигла 2,33×10⁻¹⁰ Н·м при порогах 10⁻⁸ Н и 10⁻⁸ Н·м. Максимальная
поперечная реакция одной направляющей равна 2,00036 МН в `S42-011`, сочетание 591.

Номера проверок в поставке следуют поручению. В огибающей §§4/5/6 относятся
соответственно к реакциям, прочности и устойчивости.

| Проверка | Минимальный условный коэффициент запаса | Состояние и сочетание |
| --- | ---: | --- |
| §4, осевая прочность сплошного штока | 2,89087 | `S42-001`, 2 |
| §4, прочность контрольного сечения траверсы | 0,07264 | `S42-011`, 591 |
| §5, устойчивость траверсы относительно Y, `K=2` | 0,62070 | `S42-006`, 290 |
| §6, несущая способность соединений | `null / BLOCKED_INPUTS` | Все 42 состояния |

§4 использует `235 МПа / max(abs(σ))`. §5 использует `P_cr / abs(N)` при
сжатии и сохраняет признак применимости упругого сравнения Эйлера. При ZERO
запас прочности не определяется из-за нулевого знаменателя. В `S42-007`,
`S42-017`, `S42-028` и `S42-039` удерживаемые ветви работают на растяжение,
поэтому §5 имеет статус `NOT_APPLICABLE`. Значения ниже единицы относятся
к принятым идеализированным сечениям и закреплениям.

§6 сохраняет векторные усилия, точки приложения и численные нагрузки на
крепление цилиндра, два сечения направляющих и выбранную осевую ветвь.
Упор и ветвь через замок B заданы альтернативными сценариями передачи всей
осевой силы. В открытой ветви B огибающая задаёт нулевую осевую нагрузку на
раскрытый упор и замок. Распределение сил по крепежу и несущая способность
соединений неизвестны. Численный запас требует геометрии, материалов,
характеристик контактов и допустимых нагрузок. Физические входы имеют статус
`BLOCKED_INPUTS`, физические §§4/5/6 имеют статус `NOT_RUN`.

```bash
python cae/scripts/screen_42_states.py --check-git
```

Флаг `--write` регенерирует 42 журнала, индекс, статусы и сводку осевых усилий.
Нужны Python 3.12+, Git и материализованные FCStd из Git LFS.

## Исходный аудит физических входов

Поставка по эстафете T-R3-42-STATES-01. Claim R3 принят в main
коммитом `bc42800c88d9f01b58da4d5f9d29f31e3e994783`. Сессия R3
`6afd08f5-9174-8191-ba01-ebb86011c0d3`. Хэши и исходные Git-объекты
зафиксированы в [манифесте входов](../../../coordination/tasks/T-R3-42-STATES-01/input_manifest.json).

- [Аудит по case ID](case_audit.json) содержит источник, фазу, систему координат,
  знаки, единицы, условия закрепления и определяющий пробел для каждого случая.
  42 случая имеют статус `BLOCKED_INPUTS`. Фактические нагрузки, моменты,
  опорные реакции и запасы оставлены `null`.
- [Запрос R4](r4_interface_requests.json) связывает 52 интерфейса с точными case ID.
  Для каждого интерфейса нужны источник и область применимости численных фактов,
  система осей, поза или диапазон хода, единицы, допуск при наличии либо причина
  `UNKNOWN`. Для A-V1 и A-V2 требуется подтвердить независимый путь реакции
  при пустом пуске. Для B-V1 и B-V2 нужно отразить контакты упора и замка
  при нагрузке, разгрузке, открытии и повторном замыкании. Для V2 нужны подписанные
  плечи бокового цилиндра. Для V1 требуется проверить несоосность по всему ходу.
- [Условные осевые расчёты](../../../drives/T-R3-42-STATES-01-axial.json) охватывают
  восемь именованных reference cases. Для них рассчитаны заданный осевой спрос,
  усилие и номинальное напряжение штока, проверен баланс идеальных осевых реакций.
  Входы взяты из исходных 44 привязок fixed-budget и проверены по ревизиям.
  Геометрия и двусторонние связи в этом расчёте идеализированы. Результат относится
  только к указанной модели передачи заданного усилия.

[Сверка после включения R4](r4_reconciliation.json) фиксирует SHA геометрии
`a56a62e36a1f2a1e7d1d6081d7c9ec7d5e49ab4a` и коммит её включения в main
`36d0e8a8d21c01c9867120e0dfdbe0772f7db7b6`. По манифесту сверены 42 case ID,
52 интерфейса и все 44 исходные привязки. Нативная проверка FreeCAD 1.0.0 /
OpenCASCADE 7.8.1 воспроизвела четыре FCStd. Модели дают номинальные размеры
и относительные ходы. Для фактического расчёта остаются открыты опоры, плечи,
закрепления, фазовые нагрузки и остаточные реакции. Повторены восемь условных
осевых расчётов по тем же привязкам. Для каждого физического случая сохранён
его блокер.

Из корня репозитория, Python 3.12.14 / PyYAML 6.0.3:

```bash
python cae/cases/T-R3-42-STATES-01/verify_output.py
python cae/cases/T-R3-42-STATES-01/verify_r4_handoff.py
/usr/bin/python3 -B cad/force_geometry/verify_output.py --check-git
python verify_output.py --check-git
python scripts/check_registry.py --check-git
python -m unittest discover -s tests -v
```

Первая команда повторяет расчёты и побайтно сверяет
[артефакты](output_manifest.json) с сохранёнными. Для этой поставки она использует
точные исходные привязки, каталог форка и символическую геометрию R4 из плана эстафеты.
