# Аудит 42 нагрузочных состояний REV

## Расчёт по Design Load Envelope

Для всех 42 ID воспроизведены реакции идеализированных опор (§4) и
напряжения (§5) с источником `ENVELOPE_ASSUMED` и статусом
`CALCULATED_ASSUMED`. В §5 коэффициент запаса определён как
`235 МПа / max |σₓ|` отдельно для сплошного штока и контрольного
сечения траверсы. §6 даёт наименьшую критическую силу Эйлера и
определяющее отношение `|N|/P_cr` по каждой из трёх форм и двум
закреплениям. Для фаз без сжимающих сочетаний применён `NOT_APPLICABLE`.
При `P_cr/A ≥ 235 МПа` сохранена маркировка сравнительного результата.

В [отчёте по состояниям](envelope_assumed.json) приведены векторы
реакций в определяющих сочетаниях, расчётные экстремумы и строки
[полной таблицы сочетаний](../T-R3-CAE-456-01/samples.jsonl), считая с 1.
Таблица содержит точки приложения, реакции на подвижной группе и раме
и невязки равновесия. 174 ветви с ненулевым осевым усилием и свободным
продольным перемещением имеют `NO_STATIC_EQUILIBRIUM`. Заданный контроль
`ZERO` даёт отдельную нулевую точку на каждый ID.

Для каждого физического случая сохранены `BLOCKED_INPUTS / NOT_RUN`
и значения `null` с причинами. Для усталости нужны спектр напряжений,
число циклов и данные материала и соединений. Для динамики нужны
масса и инерция, жёсткость и демпфирование, нагрузка и движение во времени.
Числа сравнения относятся к дискретной идеализированной модели.

Хэши входов и результатов приведены в [манифесте](envelope_assumed_manifest.json).
Статусы опубликованы в [реестре области огибающей](../../../params/r3_42_states_envelope_status.json).
Воспроизведение из корня репозитория с Python 3.12+ и материализованными FCStd из Git LFS.

```text
python cae/scripts/verify_42_states.py --check-git
```

Для регенерации отчёта и реестра добавьте `--write`.

## Исходный физический аудит

Поставка по эстафете T-R3-42-STATES-01. Claim R3 принят в main
коммитом `bc42800c88d9f01b58da4d5f9d29f31e3e994783`. Сессия R3
`6afd08f5-9174-8191-ba01-ebb86011c0d3`. Хэши и исходные Git-объекты
зафиксированы в [манифесте входов](../../../coordination/tasks/T-R3-42-STATES-01/input_manifest.json).

- [Аудит по case ID](case_audit.json) содержит источник, фазу, систему координат,
  знаки, единицы, условия закрепления и определяющий пробел для каждого случая.
  42 случая имеют статус `BLOCKED_INPUTS`. Фактические нагрузки, моменты,
  опорные реакции и запасы оставлены `null`.
- [Запрос R4](r4_interface_requests.json) связывает 52 интерфейса с точными case ID.
  Для каждого интерфейса нужны источник и область применимости численных фактов,
  система осей, поза или диапазон хода, единицы, допуск при наличии либо причина
  `UNKNOWN`. Для A-V1 и A-V2 требуется подтвердить независимый путь реакции
  при пустом пуске. Для B-V1 и B-V2 нужно отразить контакты упора и замка
  при нагрузке, разгрузке, открытии и повторном замыкании. Для V2 нужны подписанные
  плечи бокового цилиндра. Для V1 требуется проверить несоосность по всему ходу.
- [Условные осевые расчёты](../../../drives/T-R3-42-STATES-01-axial.json) охватывают
  восемь именованных reference cases. Для них рассчитаны заданный осевой спрос,
  усилие и номинальное напряжение штока, проверен баланс идеальных осевых реакций.
  Входы взяты из исходных 44 привязок fixed-budget и проверены по ревизиям.
  Геометрия и двусторонние связи в этом расчёте идеализированы. Результат относится
  только к указанной модели передачи заданного усилия.

[Сверка после включения R4](r4_reconciliation.json) фиксирует SHA геометрии
`a56a62e36a1f2a1e7d1d6081d7c9ec7d5e49ab4a` и коммит её включения в main
`36d0e8a8d21c01c9867120e0dfdbe0772f7db7b6`. По манифесту сверены 42 case ID,
52 интерфейса и все 44 исходные привязки. Нативная проверка FreeCAD 1.0.0 /
OpenCASCADE 7.8.1 воспроизвела четыре FCStd. Модели дают номинальные размеры
и относительные ходы. Для фактического расчёта остаются открыты опоры, плечи,
закрепления, фазовые нагрузки и остаточные реакции. Повторены восемь условных
осевых расчётов по тем же привязкам. Для каждого физического случая сохранён
его блокер.

Из корня репозитория, Python 3.12.14 / PyYAML 6.0.3:

```bash
python cae/cases/T-R3-42-STATES-01/verify_output.py
python cae/cases/T-R3-42-STATES-01/verify_r4_handoff.py
/usr/bin/python3 -B cad/force_geometry/verify_output.py --check-git
python verify_output.py --check-git
python scripts/check_registry.py --check-git
python -m unittest discover -s tests -v
```

Первая команда повторяет расчёты и побайтно сверяет
[артефакты](output_manifest.json) с сохранёнными. Для этой поставки она использует
точные исходные привязки, каталог форка и символическую геометрию R4 из плана эстафеты.
