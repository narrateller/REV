# Расчётная огибающая 42 состояний (§§4/5/6)

Область `ASSUMED_STATIC_SCREENING`. Входы, знаки, формулы и допущения заданы в
[Design Boundary & Phase Load Envelope v1](../design_boundary_phase_load_envelope/README.md).
Проверка входов воспроизводит 42 ID, 16 фаз, восемь осевых ссылок и четыре
материализованных FCStd со сверкой хэшей и исходных Git blobs. Границы задачи
определены в [постановке](../../../coordination/tasks/T-R3-42-STATES-ENVELOPE-01/task.json).
[Манифест](manifest.json) фиксирует точные входы и выходы.

## Аудит входов

- Нагрузки и относительный ход независимы. Единицы СИ: м, Н, Н·м, Па.
  Сжатие соответствует положительной силе привода и отрицательному N.
  Для полного возврата отсчёты проходятся от полного удлинения к нулю.
  В фазах упора B координата q относится к пуансону.
- Причина выбора ASSUMED — сравнение чувствительности на дискретных масштабах,
  определённых в [scoped dataset](../design_boundary_phase_load_envelope/assumptions.json).
  Моменты задаются разностью плеч привода и осевой реакции. Две направляющие
  держат только поперечные силы, знак компоненты задаёт сторону контакта.
  Для B альтернативные места упора/замка рассматриваются по отдельности.
  Нулевая нагрузка — заданный контроль. Ресурс, инерция и время цикла вне модели.
- Баланс проверяется суммой сил и векторных моментов относительно начала R4 для
  подвижной группы и рамы. Пороги абсолютной численной невязки по каждой компоненте
  составляют 1e−8 Н и 1e−8 Н·м; они относятся к вычислениям.
  Реакции фундамента, болтов и местные контактные моменты не определены.
- Напряжения сравниваются с условными 235 МПа для круглого осевого штока и всех
  четырёх углов сплошного прямоугольного сечения. Устойчивость сравнивается по Эйлеру
  для сжатия по трём сечениям/осям и двум закреплениям. Если Pcr/A достигает 235 МПа,
  модель Эйлера даёт только сравнительное число из-за выхода за принятый предел.
  Сетка и шаг времени неприменимы к алгебраической статической постановке.
- [Физические блокеры](../design_boundary_phase_load_envelope/blockers.md) сохраняются.
  Реальные нагрузки, геометрия, материалы, граничные условия и свойства контакта
  остаются неизвестными. Физические §§4/5/6 имеют статус NOT_RUN.

## Результаты и воспроизведение

В [samples.jsonl](samples.jsonl) одна строка на сочетание. Номер `row` начинается с 1.
Силы записаны как пары [координаты точки, вектор силы] в порядке X/Y/Z. Для открытой
ветви оснастки B задана нулевая осевая нагрузка на раскрытый упор и замок.
При освобождении осевой ветви ненулевая F_x создаёт продольную невязку, поэтому
реакции, напряжения и устойчивость для этой ветви представлены null с причиной.
Освобождённая ветвь проверяется по каждой ненулевой нагрузке, позе и плечу привода.
Поперечные смещения отсутствующей осевой реакции и шаг направляющих не влияют на
отсутствие продольного равновесия. При ZERO продольная степень свободы свободна.

[summary.json](summary.json) содержит диапазоны строк, статусы и определяющую строку
для каждого максимума по case ID и всему набору. При равных максимумах указывается
первая строка, остальные сочетания доступны в samples.jsonl.

Из 3672 строк 3456 относятся к удерживаемым нагрузкам, 42 к проверкам ZERO,
174 к освобождённым ветвям без продольного равновесия. Максимальная поперечная
реакция одной направляющей составляет 2,0004 МН (строка 591). Максимум |σ|
штока составляет 81,29 МПа (строка 2), а контрольного сечения — 3235,10 МПа
(строка 591, 13,77 от условного предела). Это превышение указывает на выход
линейного сравнения напряжений за условный предел.

Уменьшение шага направляющих вдвое удваивает поперечные реакции при тех же
плечах. Рост q увеличивает свободные длины и снижает Pcr. Переход от K=1 к K=2
снижает Pcr в четыре раза. Наибольшее отношение |N|/Pcr составляет 1,611 для
контрольного сечения относительно оси Y при K=2 (строка 290). Экстремум
превышает единицу в этой идеальной постановке.

Из корня репозитория с материализованными FCStd, Python 3.12+ и Git:

```bash
python cae/cases/T-R3-42-STATES-ENVELOPE-01/verify_output.py --check-git
python scripts/check_registry.py --check-git
python -m unittest discover -s tests -v
python verify_output.py --check-git
```

Для регенерации добавьте `--write` к первой команде. Проверка сравнивает сохранённые
байты и хэши без регенерации. Авторская проверка применима к принятой огибающей.
