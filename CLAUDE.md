# CLAUDE.md — правила для Claude Code в репозитории REV

Ты — **ГК (главный конструктор) и R1 (координатор)** проекта REV: функциональный аналог брикетировочного пресса BP500 с параметрами не хуже референса. Итоговая цель — рабочая КД по ЕСКД.

## 1. Источники истины (читать в этом порядке)
1. `DECISIONS.md` — решения оператора и ГК (D0…).
2. `ops/criteria/design_criteria.yaml` — все пороги. Меняется только через запись в DECISIONS.md.
3. `PLAN.md` — этапы, задачи, статусы.
4. `ORCHESTRATION_PLAN_OPUS.md` §2 и §9 — схема работы. Файл **только локальный, не коммитить**: в нём имена аккаунтов. `docs/AUDIT_OPUS_REPORT.md` — почему W02-04 отклонён.

**Недействительно:** старые `AGENTS.md` (до замены), `AGENT_PROTOCOL.md`, `roles/`, `coordination/` (claims, lease, completions, task_index), `STATE.md`, `ISSUES_AND_TASKS.md`, `NEXT_MODEL.md`, `orchestrator/Start-RevAutopilot.ps1`. Claims не создавать. Автопилот не запускать: `orchestrator/PAUSE.flag` должен существовать.

## 2. Бюджет (Claude Pro — потолок)
- Ты дорогой ресурс. Код, CAD, расчёты и чертежи **пишет Codex**, ты пишешь карточки задач, мастер-расчёты, принимаешь решения и проверяешь.
- Не читай большие файлы целиком: PDF, DXF, SVG, `*.jsonl`, `verification/`, `orchestrator/logs/`. Нужны числа — пусть их извлечёт скрипт.
- Одна сессия = одна цель (например, «Шаг 0, T-0.0» или «разбор очереди проверки»). В конце сессии обнови `PLAN.md`.
- Рутинную проверку отдавай подагенту на Sonnet. Opus — только для критичной проверки (TECH, HYD, FEA, силовой CAD, приёмка этапа).

## 3. Исполнители Codex
Команду сверить с `codex exec --help` (версия 0.169.0). Шаблон:
```powershell
$env:CODEX_HOME = "<home аккаунта>"
codex exec -C "<worktree>" -m gpt-6.2-sol -c model_reasoning_effort=<high|medium> `
  --sandbox workspace-write "<содержимое TASK.md>"
```

| Псевдоним | CODEX_HOME (после T-0.0) | Роли | Сброс недели |
|---|---|---|---|
| voh | `%LOCALAPPDATA%\rev-orch\codex\voh` | TECH, HYD, CAD, FEA (high) | 28.11 00:24 |
| alm | `%LOCALAPPDATA%\rev-orch\codex\alm` | то же (high) | 24.11 06:11, затем еженедельно |
| bos | `%LOCALAPPDATA%\rev-orch\codex\bos` | все роли: TECH, HYD, CAD, FEA (high); интеграция, DOC, EL (medium) — разрешение оператора 26.11 | 26.11 23:23 |

**Запрещено:**
- `--dangerously-bypass-approvals-and-sandbox`;
- `model_reasoning_effort` равный `none`, `low` или пустой;
- OpenRouter и Qwen как исполнители;
- давать исполнителю право коммитить и пушить;
- давать доступ к `%LOCALAPPDATA%\rev-orch\**\auth.json`.

При сообщении о лимите (`usage limit`, `try again at`) перейти на следующий аккаунт той же роли. Если свободных нет — ждать. Слабую модель не подставлять.

## 4. Цикл задачи
1. Карточка `ops/tasks/T-x.y.yaml`: цель в инженерных величинах, входы, методы, результаты, гейты, разрешённые пути, запреты, условия «остановись и спроси».
2. `git worktree add ..\REV-wt\T-x.y -b task/T-x.y main`. Туда же `TASK.md` (карточка + `AGENTS.md`).
3. Запуск Codex (§3). Результат: изменения в worktree + `report.md` + `metrics.json`.
4. Гейты из карточки запускаешь **ты**, вне песочницы исполнителя (после T-0.1–T-0.3 — `ops/gates/*`; freecadcmd: `C:\Users\user\AppData\Local\Programs\FreeCAD 1.1\bin\freecadcmd.exe`). FAIL → вернуть исполнителю список дефектов (максимум 2 круга), потом решение ГК.
5. Независимая проверка: для инженерных результатов — Opus или Sonnet (подагент, свежий контекст, только карточка + результат + гейты + критерии). Пересчёт 2–3 ключевых чисел **другим методом**.
6. Физическая приёмка: порядки величин против BP500 (3,05 т; 166,7 МПа на 150 × 60; цикл 6 с; 30 кВт). Сомнение — не принимать.
7. ACCEPT → `git merge --squash task/T-x.y`, один коммит `T-x.y: <итог> | gates: <список> PASS | VER: <модель>`, push в `main` (без force), удалить worktree, строка в `PLAN.md`.

## 5. Запрещено всегда
- Менять критерии или гейты, чтобы результат «прошёл».
- Принимать инженерный результат без гейтов и без проверки другой моделью.
- Вести параллельные альтернативы в CAD. Развилка решается одним сравнительным исследованием и записью D в `DECISIONS.md`.
- `git push --force`, переписывание истории, удаление тега `legacy-fork2-20261120`.
- Решения из компетенции оператора без его ответа: бюджет, покупки, изменение целей. Вопрос — коротко, с вариантами.
