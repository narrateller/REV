# Шаблон взаимодействия инженерных моделей — v1.2.1-candidate

Один репозиторий — один проект функционального аналога промышленного оборудования.
Вход модели: AGENTS.md → AGENT_PROTOCOL.md → STATE.md. Вход оператора:
OPERATOR_GUIDE.md. Скрипт оператора: scripts/operator_console.py. Все ворота стартуют NOT_STARTED; инженерных утверждений нет.

## Состав и проверки

- Шесть основных системных файлов: протокол, STATE, трекер, cross_check_log,
  params/registry.yaml, roles/role_profiles_summary.md.
- Универсальные домены и пять видов допусков; схема — docs/SCHEMAS.md.
- drives/cots_catalog.yaml, формы COTS, решений и арбитража.
- scripts/check_registry.py с проверкой хэшей, снимков, актов, решений, COTS,
  ссылок и ревизий. Дополнительные модули: repo_support.py, repository_checks.py.
- scripts/init_project.py с предварительной проверкой, резервной копией,
  отказом повторной инициализации и режимом --dry-run.
- .gitignore, .gitattributes и .github/workflows/ci_verify.yml.
- tests/ и изолированные синтетические fixtures; evidence/template_checks_v1_2_1.txt
  фиксирует фактически выполненные локальные проверки поставляемой версии.

```bash
python3 -m pip install -r requirements.txt
python3 scripts/check_registry.py
python3 -m unittest discover -s tests -v
```

Python 3.9+; в CI — 3.12. Зависимости закреплены в requirements.txt.
В Git-копии применять --check-git для сверки с commits. --strict запрещает
STALE в активном реестре. CI проверяет сохранённые доказательства до запуска
изолированных тестов и не генерирует их заново в рабочем дереве.

## Демонстрация

DEMO-параметры синтетические; не относятся к BP500 или конкретному изделию.
Сила вычисляется как равномерное контактное напряжение, умноженное на площадь;
не учтены инерция, трение, потери и запас. Число в примере коэффициента запаса
показывает min_only, не является рекомендацией для проектирования.
У всех параметров verifier = null. Независимая инженерная приёмка отсутствует.

Воспроизвести пример с сохранением JSON и снимка реестра:

```bash
python3 scripts/demo_force.py --write
python3 scripts/check_registry.py
```

Команда --write используется автором после расчётного изменения, не для
маскировки несогласованности в CI. После инициализации DEMO переносится в
examples/template_demo/; активный реестр PROJECT остаётся пустым. Тестовые
fixtures не считаются проектными данными и не используются для приёмки изделия.

## Ограничения автоматизации

PASS подтверждает согласованность проверяемых файлов и ссылок. Он не доказывает
истинность исходных данных, отсутствие всех чисел без регистрации, полноценность
инженерного теста, реальную независимость участников или право выпуска изделия.
GitHub workflow подготовлен; удалённый запуск и настройки ветки не выполнялись.
До их проверки enforcement остаётся PROCEDURAL.
