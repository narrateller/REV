Дата: 2026-11-09. Результат: engineering_template v1.1.
Основание: приложенный template_upgrade_and_operator_guide.md.
Изменения выполнены в комплекте шаблона; существующие репозитории изделий
и настройки GitHub не изменялись.

В v1.0 дополнительные домены уже разрешались, поэтому речь идёт о более
универсальных именах и согласованной стартовой структуре, а не снятии запрета
на аэродинамику. Пустой домен запаса был намеренным отсутствием неподтверждённой
нормы; теперь добавлен исключительно DEMO-пример, удаляемый из активного проекта.

## Исправления самого предложенного патча

1. В пояснении заявлена проверка registry_sha256, но в коде она отсутствует.
   Реализована обязательная сверка сохранённого снимка и инженерных определений
   используемых параметров. Сверка только всего текущего реестра создала бы
   ложное устаревание при добавлении review и смене зрелости.
2. script_sha256 проверялся лишь при наличии поля: удаление поля обходило
   контроль. Поле стало обязательным, добавлены хэши локальных модулей расчёта.
3. Поиск review_id через `in cross_check_text` принимал упоминание в комментарии
   или часть другого ID. Теперь читаются структурированные YAML-акты, проверяются
   точный ID, уникальность, PASS/CURRENT, параметры, соавторы, область и артефакты.
4. Наличие файла решения само по себе не подтверждает фиксацию параметра.
   Проверяются его тип, статус, покрытие параметра, review, доказательства,
   полномочия, время и отсутствие блокеров. Подлинность разрешения человека
   остаётся вне возможностей текстового валидатора.
5. Проверка Markdown в патче сверяла ID/ревизию, но не STALE и не реализовывала
   заявленные исключения для шаблонов. Добавлены обе проверки; архив и fixtures
   явно исключены из активной базы.
6. Регулярное выражение не обнаруживает все «магические числа» без ссылок.
   Такое обещание удалено. Полнота регистрации остаётся обязательной проверкой
   инженера/модели; CI гарантирует только проверяемые свойства ссылок.
7. Python считает bool разновидностью int: min_only/max_only в предложенном
   коде принимали True/False. Исправлено. Процентные отклонения выше 100% не
   запрещены произвольно; применимость и физические границы проверяются отдельно.
8. Инициализатор из патча безусловно заменял реестр и удалял файлы. Новый
   отказывает при PROJECT/проектной работе, поддерживает --dry-run, сохраняет
   backup и DEMO-примеры, откатывает изменяемые файлы при обычной ошибке записи.
   Аварийное прерывание процесса требует проверки lock/backup оператором.
9. `.gitignore` не скрывает все *.log: журналы решателя могут быть доказательством.
   LFS-паттерны учитывают .FCStd и другой регистр. CI использует lfs: true;
   недоступный LFS-объект не считается прочитанным исходным файлом.
10. Наличие workflow не переводит enforcement в ENFORCED и не настраивает
    защиту GitHub. Инструкция содержит отдельную проверку серверных настроек.
11. В таблице замечаний было «после 2 возвратов», в патче — «более двух».
    Принят однозначный порог второго возврата по тому же конфликту.
12. Из регламента исключены обещание запуска за фиксированное время и
    универсальные пороги ресурса/отстройки от резонанса. Модели измельчения
    и показатели разделения требуют собственного определения и обоснования;
    они не объединяются в единый универсальный критерий.

## Проверки и границы результата

В tests/test_repository.py находятся 48 автоматических тестов. Все выполнены
успешно локально. Среди них — положительная проверка review по реальному commit
в изолированном тестовом Git-репозитории, проверка целостности манифестов,
отказ повторной инициализации и восстановление после искусственной ошибки записи.
Тестовые подписи/решения создаются только во временных fixtures; они не являются
инженерными актами проекта. Полный журнал: evidence/template_checks_v1_1.txt.

Структурный валидатор выполнен в строгом режиме. Отдельно проверяются упаковка,
Git-атрибуты и запуск из распакованного комплекта; журнал — evidence/smoke_checks_v1_1.txt.
GitHub Actions на удалённом репозитории не запускался, branch protection не
настраивалась. Физические испытания и инженерная приёмка изделия не выполнялись.

## Перенос существующей v1.0

Для нового проекта использовать полный архив v1.1. Для уже начатого проекта
не запускать init_project.py: он не предназначен для миграции или сброса.
В отдельной ветке обновить системные файлы с сохранением действующих задач,
STATE, решений и параметров; переименовать домен, установить schema_version 1.1,
добавить author_sessions и code_files. Прежние доказательства не переподписывать:
пересчитать затронутые результаты с сохранением снимков, переоформить акты в
машинную схему и провести независимую проверку. Нет доказательств — нет VERIFIED.
