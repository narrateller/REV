# Формат эстафеты следующей модели

Применить к NEXT_MODEL.md при любом завершении задачи, не только при нехватке
контекста. Заполняются конкретные данные; эта форма не является назначением.

- Состояние: READY / BLOCKED / HANDOFF; UTC; session_id и роль автора.
- Проект: project_id, точный repo/branch, полный commit C результатов.
- Задача: ID, статус, затронутые ворота, владелец и claim/lease.
- Проверенный результат: файлы и методы, точные ревизии параметров, проверка.
- Входы следующего участника: commit, ссылки на файлы, параметр ID@revision,
  источник и область применимости.
- Незакрытое: ID блокеров, вопросы, UNKNOWN/ASSUMED, риски и ограничения.
- Следующая подходящая роль: R1–R6, основание, требования независимости,
  наличие действующего подтверждения роли. Не выдавать предложение за назначение.
- Первое атомарное действие: файл/формула/узел, команда при необходимости,
  критерий успеха; что делать при недоступных данных.
- Капсула, входной/выходной review, вопросы оператору, если действительно нужны.
- Доступность C и рабочей ветки: REMOTE / LOCAL_ONLY / UNSAVED.

Создать commit C с результатом, затем commit H с обновлённым STATE, полной
капсулой и NEXT_MODEL.md, ссылающейся на C. Если push недоступен, передать
пользователю капсулу и patch; не утверждать, что другой участник их увидит.
Представить пользователю короткую команду:

> Войди в курс дел и текущий статус проекта; прочитай AGENTS.md, STATE.md и NEXT_MODEL.md.

Если подключение не привязано к проекту, добавить URL репозитория и ветку.
