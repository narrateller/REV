## Порядок работ

| Задача | Приоритет и состояние | Действие |
| --- | --- | --- |
| `T-R3-42-STATES-01` | P0 / `DELIVERED_BLOCKERS_REMAIN` | 42 результата по огибающей имеют `CALCULATED_ASSUMED`. Возврат к физическому расчёту после получения определяющих входов. |
| `T-R4-W02-CAD-01` | P1 / `READY_INPUT_AUDIT` | Следующая задача из порученных вариантов R3/R4. Проверить готовность к пересборке в области `REBUILD_READINESS_FOLLOWUP`. Предыдущий документальный аудит завершён и принят. |
| `T-R2-INPUTS-01` | P0 / `READY` | Сохраняет приоритет общей очереди. Подготовить подтверждённые входы, необходимые для снятия физических блокеров. |
| `T-R4-DRAWINGS-01` | P1 / `WAITING_ENGINEERING_BASELINE` | Продолжить после воспроизводимой пересборки W02 и готовности инженерной базы. |

1. R4 получает свежую `origin/main`, проверяет отсутствие конкурирующего владельца и
   публикует claim со своим фактическим Codex session ID и новым lease. В постановке
   указан шаблон с незаполненными полями исполнителя. [Передача R4](../../completions/T-R4-W02-CAD-01/handoff_R4.md)
2. R4 проверяет доступность FreeCAD, актуальность входов и границы применимости
   огибающей. При достаточных входах выполняет пересборку редактируемой CAD и экспорт
   в явно указанной области. При пробелах сохраняет проверенные факты, причины и
   статусы `BLOCKED_INPUTS` или `NOT_RUN` для затронутых критериев.
3. R1 сопоставляет выход R4 с опубликованными входами и направляет в R3 только
   затронутые case ID, когда изменения входов влияют на расчёт. После появления
   нового инженерного результата R1 ставит R5 отдельную проверку по точному SHA.

Оператор разрешил применять расчётную огибающую с зарегистрированными
допущениями. Для 42 физических состояний и несущей способности соединений
сохраняется `BLOCKED_INPUTS`, для физических §§4/5/6 и пересборки W02 сохраняется
`NOT_RUN`. Определяющие `UNKNOWN` записываются как `null` с причиной. Физические
испытания и выпуск в производство требуют отдельного решения человека.
