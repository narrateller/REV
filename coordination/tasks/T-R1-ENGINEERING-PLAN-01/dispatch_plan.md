# Эстафета R3 и R4

План подготовлен R1 `6afd05ce-c548-8191-8743-6db04ec380eb` по команде оператора от 2026-11-18. [Манифест входов](input_manifest.json) фиксирует исходную `main`, точные объекты Git и назначенные сессии. Аудит R1 подтвердил соответствие трёх исходных тегов манифесту форка, хэш активного реестра и наличие 42 уникальных записей со статусом `NOT_RUN` на момент форка.

## Принятие claims

1. После включения этого плана в `main` R3 `6afd08f5-9174-8191-ba01-ebb86011c0d3` готовит и включает новый claim `T-R3-42-STATES-01` в свежую `main`. Перед включением он проверяет фактический ID, точный SHA, отсутствие конкурирующего claim по задаче и других задач у этой сессии, входы и фактический UTC. Инженерный аудит начинается после подтверждения claim на сервере.
2. После появления claim R3 в `main` R4 `6afd08ad-4ce0-8191-b3bb-3a3b2bc1d050` получает свежую `main` с этой записью и последовательно включает свой claim `T-R4-FORCE-GEOMETRY-01` с теми же проверками. Если `main` продвинулась, проверь новый SHA, владельцев и входы перед повторной попыткой. Оба claim действуют в пределах собственных новых lease по `AGENT_PROTOCOL.md`.

Работа идёт в отдельных ветках от принятых claims. Прямые обновления `main` выполняются обычным fast-forward только для последовательного принятия claims. Результаты включаются обычным merge после проверки точной головы и CI. При конкуренции перечитай `main` и сохрани свою ветку. Файлы claims разных задач независимы.

## Параллельный аудит и области записи

| Роль | Область записи | Передача |
| --- | --- | --- |
| R3 | `cae/cases/`, относящиеся к задаче файлы `drives/` и собственный пакет проверки | Аудит всех 42 case ID по зафиксированному каталогу. По каждому случаю укажи источник нагрузки, единицы, знак, frame, условия закрепления и зависимость от интерфейса. Передай R4 конкретный список интерфейсов и нагрузочных случаев, требующих уточнения. Расчёт по достаточным входам может идти параллельно. |
| R4 | `cad/source/`, относящиеся к задаче скрипты CAD и собственный пакет геометрии | Для четырёх вариантов передай редактируемые исходники, команду rebuild, версии FreeCAD/Part, хэши и соответствие `case ID → interface ID → геометрический факт или UNKNOWN`. Зафиксируй опоры, эксцентриситеты, свободные длины, сечения, материалы и двусторонние связи с источником или причиной UNKNOWN. Изменения исходных 44 привязок и ходов оформляй с причинами и версиями. |

Общий `params/registry.yaml` служит исходным входом обеих веток. Если понадобятся изменения, оформи предложение с ID, ожидаемой ревизией, причиной и входами в пакете своей задачи. Включай изменения последовательно при интеграции с проверкой актуальных ревизий и повторной валидацией затронутого пакета. Сводные `STATE.md`, `ISSUES_AND_TASKS.md`, `NEXT_MODEL.md` и `coordination/task_index.json` обновляются при интеграции, чтобы рабочие ветки не правили общую очередь одновременно.

## Порядок включения результатов

1. **R4 → `main`.** Проверь точную голову пакета геометрии, манифест файлов и версий, воспроизводимость rebuild для поставленных моделей, привязку к интерфейсам, открытые UNKNOWN и обязательные проверки CI. Передай R3 SHA включённого пакета и путь манифеста. Если часть геометрии остаётся заблокированной, зафиксируй достаточные факты и конкретные недостающие входы. Решение о включении частичной поставки принимается по её фактической области и критериям задачи.
2. **R3 → `main`.** После геометрии R4 получи свежую `main`, зафиксируй точный SHA геометрии, сверяй затронутые интерфейсы и повтори затронутые проверки или прогоны. Сохрани итог для всех 42 ID. `CALCULATED` требует выполненного прогона и проверяемых результатов в явно указанной области. При определяющем пробеле укажи `BLOCKED_INPUTS` или `NOT_RUN` и причину. Перед merge проверь точную голову, актуальные входы, claim, срок, отсутствие конкуренции и CI. При завершении каждой задачи освободи её claim в `main`.
3. **R5.** `T-R5-ENGINEERING-VERIFY-01` остаётся `WAITING_RESULTS` до поставки проверяемых результатов. Для проверки передаются точные SHA, манифесты, команды воспроизведения и ограничения.

Обязательные проверки из корня репозитория

```bash
python verify_output.py --check-git
python scripts/check_registry.py --check-git
python -m unittest discover -s tests -v
```

Этот этап завершает координационную задачу. G1 остаётся открыт, W02 и физические испытания остаются за пределами эстафеты.
