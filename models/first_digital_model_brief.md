## Цель и точный объём

Первая модель — параметрическая геометрия и кинематика двух альтернатив
пресса A/B, с последовательностями из controls/press_variant_state_tables.md.
Нужен воспроизводимый проверяющий инструмент для позиций/ходов/огибающих,
а не реалистичная картинка, расчёт усилий или симуляция древесины.
Архитектура не выбирается: обе альтернативы остаются активными.

Входные эскизы: concepts/press_functional_alternatives.md, исходная версия
в `6fe0a417ed2fde165e2fc01d625ec86ab810346e`; текущие таблицы циклов и это
задание сохраняются одним атомарным набором. Источники сырья — process/feedstock.md.
Точные ревизии/commit фиксирует исполнитель при claim после принятия задания.
Никаких данных BP500-ANALOG; размеры/усилия и численные значения UNKNOWN.

## Реализация первой итерации

Предлагается Python 3.12 и стандартная библиотека: 2D огибающие/контуры и
воспроизводимые SVG схемы положений плюс JSON отчёт о проверках. Это позволяет
начать без неподтверждённого CAD-пакета. Две проекции с явными координатами/
положениями по высоте лучше одной; если геометрии недостаточно для вывода,
возвращать INDETERMINATE. Проекционное пересечение — потенциальная коллизия,
не всегда физическое столкновение; полноценная 3D/CAD проверка — следующий этап.

Детализировать не крепёж, а габариты/кинематические связи: корпус/рама,
крепления цилиндра и направляющих, пуансон, загрузочное окно/затвор,
объём движения дозатора, канал/зажим A либо упор/замок B, пространство
выдачи и условный габарит изделия. Топологию силового контура показать,
прочность не вычислять. Положение центра/осей/контуров задаётся входами;
никакая незаданная координата не приравнивается нулю.

## Входной контракт

| Группа входов | Нужные поля | Текущее состояние / происхождение |
|---|---|---|
| Геометрия | Система координат, контуры корпуса/камеры/окна/дозатора/затвора/канала/упора/замка и выхода, внеплоскостные ограничения | UNKNOWN; получить собственным параметрическим построением, не копией размеров промышленных машин |
| Движения | Оси/направления, крайние положения и рабочие/выдающие ходы, ограничения направляющих, последовательность | Направления/порядок — кандидат из эскизов, значения UNKNOWN |
| Изделие | Условная оболочка продукта и её положение после хода/при выдаче | UNKNOWN; это вход для габаритной проверки, не смоделированный результат уплотнения |
| Разрешения | Таблицы состояний, совместимость движений, наличие геометрических подтверждений | Из текущего документа циклов; материал/силовые разрешения задавать UNKNOWN, не выводить из координат |
| Зазоры/погрешности | Сборочные допуски, проверяемые расстояния и неопределённости | UNKNOWN; не вводить произвольный «безопасный запас» |

Входной шаблон хранит null/UNKNOWN для незаданных величин и список единиц/
правил представления. Единицы и параметры должны иметь явные определения;
проектные численные значения — в params/registry.yaml до инженерного
использования. Размеры/усилия сейчас не назначать. При отсутствии чисел
выдать символическую схему и список недостающего; не строить фиктивную
готовую конструкцию и не сообщать PASS для её пересечений.

## Критерии готовности задания к приёмке после реализации

- Обе альтернативы воспроизводятся одной документированной командой с явными
  параметрами; незаданные входы дают список зависимостей/INDETERMINATE.
- Весь ход каждой разрешённой фазы/совместного движения проверен непрерывным
  методом либо консервативной оценкой между отсчётами с обоснованной полнотой
  обнаружения. Одной проверки крайних/дискретных положений недостаточно. Если
  метод не гарантирует обнаружение возможной коллизии, результат соответствующей
  проверки INDETERMINATE, а не NO_COLLISION. Перестановка фаз не скрывает пересечение.
- Выполнены пять обязательных синтетических случаев с ожидаемыми результатами
  из таблицы ниже; дополнительно проверяются противоречивые входы. Синтетические
  случаи проверяют поведение модели, не физическую работоспособность пресса.
- Привязаны REQ/VAL-REV-05/06/09/11/12/16; геометрические выводы отделены
  от вопросов сырья/сил/реального изделия. Нельзя пометить весь VAL выполненным
  по одному результату цифровой модели.
- Независимый reviewer проверил постановку/метод и точный результат; выбор
  A/B, прочность, критерии реального брикета и G1 не считаются утверждёнными.

## Обязательный контракт пространственной и временной проверки

Результат относится к конкретным телам, фазе, временному интервалу и явно
заданной геометрической области модели, а не к реальной конструкции REV.
Разделять следующие признаки и не подменять один другим:

| Признак | Что означает | Какой вывод допустим |
|---|---|---|
| Пересечение 2D-проекций | Наложение проекций заданных тел/их областей движения | Кандидат на помеху. Без достаточных внеплоскостных данных не доказывает реальную коллизию |
| Пересечение траекторий | Общие пространственные точки заданных опорных траекторий без учёта времени прохождения | Не доказывает одновременного присутствия тел; отсутствие пересечения опорных траекторий также не доказывает разнесения тел конечного размера |
| Пересечение пространственных огибающих всего хода | Области, посещаемые телами хотя бы когда-либо, перекрываются | Консервативный отбор потенциальных пар, но не доказательство столкновения в один момент времени |
| Столкновение тел в один момент времени | Объёмы/контуры тел пересекаются при одном и том же t согласно выбранной политике контакта | COLLISION только при доказанном общем времени и геометрическом свидетельстве в объявленной области модели |

Для каждой пары/фазы результат `collision_status` принимает COLLISION,
NO_COLLISION, INDETERMINATE или INVALID_INPUT. NO_COLLISION требует
доказанного отсутствия столкновения **на всём проверяемом интервале**, а не
только отсутствия пересечения в просмотренных кадрах. COLLISION требует
свидетельства общего момента/интервала; одно перекрытие консервативных
огибающих не достаточно. Для потенциальной помехи/проекций сохранять
отдельный диагностический признак и основания, не выдавать его за COLLISION.

Метод должен учитывать согласованное во времени положение каждого тела,
включая совместные движения и возврат. Допустим непрерывный аналитический
метод или консервативное ограничение движения внутри каждого интервала
с последующим уточнением. Редкая/адаптивная сетка без доказанной границы
пропуска не является гарантией. Если после уточнений пересечение нельзя
доказать или исключить — INDETERMINATE. Критерии контакта/касания, геометрическая
точность и погрешности должны быть явно заданы для вычисления; неизвестные
значения, влияющие на вывод, не заменяются произвольным допуском.

Отсутствующая необходимая координата, толщина/интервал по высоте, контур,
траектория или синхронизация приводит к INDETERMINATE для зависимой проверки.
Не подставлять нули, неподвижность или последовательность движений по умолчанию.
Противоречивый вход даёт INVALID_INPUT. Отчёт содержит статус каждой проверки,
её зависимые/недостающие параметры, область 2D/условных 3D-примитивов, интервал,
метод/основание полноты, диагностические пересечения, доказательство разнесения
либо свидетельство столкновения. Не сворачивать неизвестные проверки в общий PASS.

Первая реализация должна уметь обосновать известное разделение по высоте на
простых синтетических телах, например заданных плоских контурах с интервалами
экструзии. Это не требует полного CAD, но требует учёта внеплоскостной геометрии.
Пересечение нескольких проекций само по себе не является общим доказательством
столкновения произвольных 3D-тел; всё вне поддержанного класса — INDETERMINATE.

Для выдачи отдельно хранить `ejection_status`: SUFFICIENT_STROKE,
INSUFFICIENT_STROKE, INDETERMINATE или INVALID_INPUT. Проверяется геометрический
вывод заданной оболочки изделия до границы выхода, не реальная выдача при трении.
Корректно заданный короткий ход — INSUFFICIENT_STROKE, не противоречивый вход
и не обязательно коллизия. `collision_status` при этом вычисляется независимо.

## Пять обязательных синтетических случаев

Все fixtures — изолированные условные геометрии/траектории, не параметры REV.
Для каждого заранее указать тела, полный ход/временной закон, область модели,
политику контакта и независимое обоснование ожидаемого результата.

| ID | Полностью заданная ситуация / условие | Ожидаемый результат |
|---|---|---|
| SYN-MODEL-01 | В начальном и конечном положениях тела разнесены, внутри хода есть доказанное одновременное пересечение | collision_status = COLLISION; свидетельство внутри интервала, свободные концы не дают NO_COLLISION |
| SYN-MODEL-02 | Проекции перекрываются, но известные объёмы простых тел разделены по высоте на всём интервале; полного описания достаточно для доказательства | Диагностика пересечения проекций = true, collision_status = NO_COLLISION для заданных тел/интервала; основание — разнесение объёмов, не ложная коллизия от проекций |
| SYN-MODEL-03 | Опорные траектории пересекаются, тела проходят общую область в разные моменты; размеры и временные законы заданы так, что объёмы одновременно не пересекаются нигде в ходе | Диагностика пересечения траекторий = true, collision_status = NO_COLLISION на всём интервале; независимое обоснование учитывает конечные размеры, а не только разное время прохождения центров |
| SYN-MODEL-04 | Отсутствует геометрия/толщина либо траектория/синхронизация, необходимая именно для проверяемого вывода; остальные данные не позволяют независимо доказать разнесение/коллизию | collision_status = INDETERMINATE со списком недостающего; не нули, не NO_COLLISION и не необоснованный COLLISION. Проверить подслучаи недостаточной геометрии и траектории |
| SYN-MODEL-05 | Геометрия камеры/изделия/выхода и закон хода полностью заданы; при максимальном ходе изделие ещё не достигает границы полной выдачи, препятствий/коллизий в примере нет | ejection_status = INSUFFICIENT_STROKE; collision_status = NO_COLLISION по независимой полной проверке; отсутствие столкновения не означает достаточный ход выдачи |

Для SYN-MODEL-01 ответ INDETERMINATE вместо выдуманного NO_COLLISION безопасен
по контракту, но не означает прохождение эталонного случая: задача полного
обнаружения для поддержанного класса примитивов ещё не выполнена. Аналогично
необоснованный общий INDETERMINATE вместо доказуемых результатов SYN-MODEL-02/03/05
не считается выполнением этих обязательных случаев. Результаты fixtures и
ограничения метода должны быть отдельно проверены независимым reviewer.

## Что эта модель не решает

Нужны пробы/опыты для сводов и массы доз, кривых уплотнения, трения, удержания
столба, пружинения/остаточного усилия упора, отделения/разрушения и реального
выталкивания. Нужен собственный расчёт после нагрузок для силового контура,
цилиндров/рамы/замка, гидравлики и тепла. Их нельзя подменить геометрической
анимацией. Пробы и опыты остаются отложенными; испытания не запускались.
Следующий этап — независимая проверка задания, назначение исполнителя/claim;
архитектуру не утверждать, G1 оставить открытым.
