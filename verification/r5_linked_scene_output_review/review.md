## Независимые воспроизводимые контрпримеры

Файлы `probe.py` и `probe_results.jsonl` расположены рядом с актом; SHA-256 соответственно `c85883ceb7705c9104668bd0157d6e85084a293caf5fa7a33cf1b83aaa70baba` и `af50c1928552759059cc7ae2bef39b821f594364fd5cbcf917c54e81293fd5ed`. После указанного `git archive` из корня акта выполнить:

Assertions в probe фиксируют **фактически полученное ошибочное поведение** и позволяют воспроизвести контрпримеры на C; их успешный exit не означает, что реализация прошла review. Вывод включает ожидаемые результаты и полные данные результата.

**R5-LINKED-IMPL-B01 — OPEN: доказанное исчезновение остатка скрыто неизвестным CREATE.** В `boundary` предыдущее множество содержит `residue_1`, следующее — только `product_new`; для исчезновения остатка нет REMOVE, а для нового тела указано неподдержанное CREATE. Сначала определяется недопустимое исчезновение, но ветка `if added` перезаписывает `event_status='INVALID'` значением INDETERMINATE. Возвращено только `status=INDETERMINATE`, хотя `removed` показывает отсутствие остатка. Контракт требует сохранять доказанный разрыв независимо от неизвестного события; зависимый переход должен быть BLOCKED, а неизвестный CREATE отражён отдельно. Исправить агрегацию и сохранить оба доказательства; добавить негативную проверку исчезновения вместе с CREATE/SPLIT и иными INVALID/UNKNOWN.

**R5-LINKED-IMPL-B02 — OPEN: неподдержанное событие игнорируется без изменения реестра.** Если тело остаётся прежним, а во входных events указан CREATE другого ID без добавления его в реестр, `boundary` возвращает `CONTINUOUS` и `lifecycle_status=VALID`: список событий проверяется только через разность `old/new`. Неподдержанный CREATE не может стать подтверждённым; в этом несогласованном примере допустима явная классификация INVALID_INPUT по противоречию либо INDETERMINATE при обработке неподдержанного события, но не VALID/CONTINUOUS. Валидировать каждое событие, его ID, время, тип и соответствие реестру и сохранять неподдержанное состояние; аналогично проверить SPLIT, лишние события и дубликаты. Обычные случаи CREATE и SPLIT с изменившимся реестром в probe действительно дают INDETERMINATE; это не снимает блокер.

**R5-LINKED-IMPL-B03 — OPEN: связь подтверждается при нулевой площади контакта.** README C заявляет контакт передней x-грани и задней x-грани с положительной yz-площадью. Для неподвижных `a=[(-1,0,0),(0,1,1)]` и `b=[(0,1,0),(1,2,1)]` их соприкосновение — ребро с нулевой шириной по y. `classify` допускает `contact_lo <= contact_hi`, и `pair` возвращает ALLOWED_CONTACT на всём интервале и LINK_CONFIRMED. Это не удовлетворяет заявленной положительной площади. Определить и реализовать строгую положительную площадь в обеих осях, отдельно классифицировать вырожденное касание без ложного LINK_CONFIRMED, добавить точечные/рёберные, граничные и малые положительные случаи. Реальная сила при этом остаётся UNKNOWN.

**R5-LINKED-IMPL-W01 — OPEN: эквивалентные представления времени.** `boundary` сравнивает значения исходных меток напрямую: `[0, '1']` и `[1, 2]` дают `time_contiguous=false` и DISCONTINUITY, хотя `q` допускает целое и рациональную строку, а значения равны. Сравнивать валидированные точные рациональные значения и аналогично сверить время событий; предусмотреть INVALID_INPUT для противоречивых/невалидных данных. Это ложное блокирование, а не подтверждение безопасности.
