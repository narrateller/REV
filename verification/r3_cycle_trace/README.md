## Основные результаты

- До геометрического исправления требуется определить материальное состояние: первоначальное заполнение A, удерживаемый столб и стационарная выдача либо single-product модель; для B — набор/предуплотнение/реальная выдача и остатки. Готовый product surrogate не доказывает загрузку/уплотнение сырья.
- PRODECO показывает начало прессования после полностью закрытой feed box и удержание материала на возврате, но REV имеет иной дозатор/затвор. Нужна собственная межузловая таблица состояний; end timestamp не является обратной связью.
- Сохранённые CAD-сцены имеют rod–chamber/feed penetration witnesses и потерянные интерфейсы clamp/channel A. Числовые контексты и записи проверены, native/BRep прогоны заново не выполнялись; источник не подменяется независимым геометрическим review.
- Фактический выход CAD отличается от упрощённого R3. Для single-product surrogate SHORT_STROKE остаётся; для стационарного A сначала определить выходящий сегмент/столб, а не автоматически растягивать ход на всю длину канала. Нельзя удалять продукт/укоротить канал ради PASS.
- ARS разделяет давление/partial position, backoff, дверь, выдачу и возврат. Его source timer не критерий разгрузки REV. B-UNLOAD не подтверждает снятие реакции, B open INDETERMINATE; RESET B через оставшийся продукт даёт зарегистрированное противоречие.
- CAD full diagnostic duration включает дополнительные стадии вне R3 main-axis budget. Это не новый согласованный цикл/производительность: подачи/зажим/дверь/одновременность/потребление требуют собственного общего графика. Полный реальный цикл UNKNOWN/INDETERMINATE.

Все REV-переходы в таблице — **ASSUMED функциональные предложения с пробелами**, не утверждённая архитектура/контроллер. Статус BLOCKED_IN_DECLARED_CAD_MODEL сохраняет конкретный отрицательный исход данной сцены. UNKNOWN не превращён в ноль/PASS; источники с другим сырьём/исполнением не передают численные требования автоматически. Материальные условия приведены по source IDs в ledger и в каждой строке, а не одной общей ссылкой «аналог».

## Проверяемость и неизменность

Из /workspace/REV:

```bash
.venv/bin/python -B verification/r3_cycle_trace/verify_trace.py
.venv/bin/python -B verification/r3_cycle_trace/render_documents.py
sha256sum -c verification/r3_cycle_trace/artifacts.sha256
.venv/bin/python -B scripts/rev_parametric.py
.venv/bin/python -B scripts/rev_power_reconcile.py
.venv/bin/python -B scripts/check_registry.py --check-git
```

Первый скрипт читает exact Git blobs CAD, сверяет extract, покрытие стадий/вариантов, ссылки источников/ID/фаз/узлов/backlog и 88 защищённых расчётных файлов. `--capture` сохраняет **только новый документальный extract в этой папке**, не вызывает solver/CAD generation. Он нужен для воспроизведения выписки, не для исправления исходного пакета. Остальные команды readonly; `--write` защищённых моделей не используется.

`render_documents.py` без аргументов сверяет три Markdown-таблицы с JSON и ничего не записывает; `--render` воспроизводит только новые таблицы этой задачи. Исходные сценарии/оба акта R5 сохраняются. В ресурсных строках приведены существующие BASE_A/B fixed-budget и fixed-times значения из реестра: условные peak/average/energy bounds и MASS_RATE с исходным main-axis знаменателем. Они не подтверждают полный цикл или реальную производительность. Fixed-budget остаётся условной базой с caps и увеличенными временами; fixed-times требует отдельного неутверждённого ресурса питания.

Для будущего ресурсного графа R4/R3 требуются разные входной и сливной расходы, давление каждой полости и интервалы одновременности. Для общего насоса нельзя ограничиться суммой механических мощностей штоков: расход всех активных ветвей проходит при выбранном давлении подачи, с потерями в регулировании и обратных линиях. Выдержка/разгрузка/standby включают насос, утечки и вспомогательные потребители по схеме; ни один неизвестный член здесь не принят нулевым. Формулы и границы проверенного расчёта сохраняются в [model.md](../r3_parametric_sizing/model.md) и [model.md](../r3_power_reconcile/model.md). Новые движения потребуют отдельного пересмотра этих входов, а не правки проверенных чисел в этой задаче.

Текущая задача не меняет scripts/tests/params/evidence расчёта и CAD/генераторы/native/STEP. Не выполнялись физические испытания, независимый native replay, новые расчёты прочности/материала или подбор оборудования. Источник CAD существует в Git/LFS на указанном C; полный native пакет здесь не материализован и не пересохранён. Положительные native witnesses — сохранённые авторские данные R4, а не новая проверка настоящей сессией. Source OCR — навигация, а не самостоятельное доказательство текста схем; перечисленные визуально прочитанные страницы указаны отдельно.

Визуальные страницы воспроизводятся `/usr/bin/pdftoppm -f PAGE -l PAGE -singlefile -scale-to 1700 -png sources/raw/FILE.pdf /tmp/view`; текст — `pdftotext -layout`. ARS — скан, для навигации использовался tesseract с OMP_THREAD_LIMIT=1; существенные страницы/flowchart прочитаны по изображению. Версии/подлинность изготовителей вне локальных копий и приложения, не прочитанные фактически, не удостоверены.

Архитектура/ТЗ/оборудование не утверждены, G1 OPEN, B opening и полный цикл INDETERMINATE, физические испытания NOT_RUN. Девять пунктов R4 остаются OPEN до отдельного согласования/реализации/проверки; в этой задаче изменений геометрии нет.

Результаты запусков этой задачи — result_checks.json и result_*.log; сохранность — result_preservation.json. Прежние checks.json/preflight.json/registry_check.log относятся к предложению claim и сохраняются как история. artifacts.sha256 фиксирует состав документального C; его точный Git SHA и следующий H публикуются в STATE/NEXT/капсуле, без встраивания SHA коммита внутрь него самого.
