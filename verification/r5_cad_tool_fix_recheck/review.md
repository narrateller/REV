Таким образом, прежний manifest-only PASS устранён, а основные тела не принимаются только по хэшам/габаритам. Для повреждённых файлов с обновлённым хэшем реально вызывался нативный подпроцесс и фиксировался его failure. **R5-CAD-TOOL-B02-Q01 — OPEN: подменённая геометрия QueryVolumes всё ещё получает CAD PASS.** Временная копия FCStd A: у `CylinderRemoval` удалено выражение Height (`2 * Inputs.param_82 + Inputs.param_371`) и высота изменена с **1740 до 99999 мм**. Это исключительно synthetic-контрпример reviewer, не изменение исходных исследовательских чисел. Независимый вызов CLI `check_layout.py --inputs … --models … --out …` также дал exit 0, status=COMPLETED_WITH_KNOWN_INTERFERENCES и CAD PASS обоих вариантов.

Причина: `native_validate` проверяет имена QueryVolumes и Role, но не их форму/положение/размеры по принятым ASSUMED-входам; затем исключает эти объекты из проверки геометрии основных solid. Подтверждение основных solid не должно выглядеть как подтверждение всех нативных геометрических артефактов.

**Обязательное исправление B02:** проверить нативные параметры/форму/положение CylinderRemoval/DoserRemoval против воспроизводимого определения из входов, включая их статус QUERY_NOT_SOLID, и добавить регрессии подменённых зон при обновлённых хэшах. Либо явно ограничить заявляемый PASS основными телами, вывести отдельный NOT_RUN/FAILED для непроверенной геометрии зон и не объявлять полное соответствие CAD заданию.
