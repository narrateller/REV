# T-r4-force-geometry-01 — предложение отдельной условной задачи R4

TASK / P1 / родитель T-INIT; потребители R3/R5/R6. Статус PROPOSED,
execution BLOCKED_PENDING_SEPARATE_CLAIM, owner_session NONE, lease_expires_at null.
Назначение, session, срок и последовательное принятие claim должны быть оформлены
отдельно; истёкшие полномочия прежних задач не используются.

Цель: подготовить прослеживаемую условную геометрическую постановку
A-V1/A-V2/B-V1/B-V2 для последующего профильного расчёта. Архитектуру не выбирать,
общий native CAD-rebuild и изменение действующего CAD не выполнять.

## Результат и критерии

1. Для каждой топологии задать систему координат, узлы корпуса/штока/захвата/
   портала/отдельного носителя/пуансона, направляющих, реакционного узла и рамы.
   Описать свободные степени свободы, контактные стороны, опоры и передачу обоих
   знаков усилия. Односторонний толкатель не считать двусторонним захватом.
2. Подготовить символические e_y(q), e_z(q), шаг/направления опор, L_free(q) штока
   и отдельного носителя для полного исходного хода, частичных и промежуточных поз.
   V1: несоосность не принимать нулевой; V2: обе плоскости/пространственный вынос,
   портал и swept-volume/сервисные ограничения. Не объявлять CAD collision CLEAR.
3. Отдельно описать A/I_y/I_z/W_y/W_z/J носителя/портала/штока, материалы, E,
   закрепления, дефекты и жёсткости. Реальные неизвестные значения UNKNOWN/null
   с причиной/владельцем получения. Не копировать диаметр штока в сечение носителя.
4. Перечислить двусторонние joints и COTS interfaces: геометрия групп, пальцы/
   болты/резьба/сварка, контакт/люфт/преднатяг, монтаж цилиндра/направляющих/упора,
   отрыв/срез/смятие/обратный момент/боковая нагрузка. Равное распределение не задавать.
5. Сопоставить с 42 строками условий без заявления их расчёта. A startup/retention,
   B unload/unlock/open/reset, F(q,t), массы/ускорения/трение и остаточные нагрузки
   запросить у R2/R3; критерии прочности/устойчивости — R5/R6/R1. При неизвестном
   контакте/нагрузке соответствующая реакция, запас и capacity остаются UNKNOWN.
6. Новые количественные гипотезы — только отдельные ID/revision/ASSUMED с
   основанием/областью и sensitivity plan; не переносить scoped R3F в active CAD.
   Все 44 привязки, нагрузки/ходы/fixed-budget/исходный CAD и история должны совпасть
   побайтно; необходимость изменения baseline оформить отдельным запросом.
7. Выход: таблица геометрических интерфейсов и пробелов по четырём вариантам,
   схемы/символические зависимости, manifest/сохранность, C/H и независимый R5
   review request на exact C. Результат не становится VERIFIED/LOCKED до процедуры.

Успех — комплектная условная постановка с явными UNKNOWN и трассировкой, а не
доказательство реализуемости. Срок/владелец получения каждого реального входа
согласуются отдельно; текущий документ не назначает чужих claims.
