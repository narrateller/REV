# CYC-01 — материальный контракт A/B, редакция 2

**Коррекция разрешений — редакция 2:** L1–L5/материальный словарь сохранены;
contract.json теперь задаёт entry/completion и обязательные READY bindings.
См. [permissions.md](permissions.md): разрешение действия, commit результата и
учёт факта раздельны. Даже неразрешённое фактическое поступление сохраняется в
ожидающей сверки записи; отказ не стирает вещество. Утверждения о завершении
шага ниже относятся к подтверждённому commit, не к одному запросу его старта.

**Статус: ASSUMED_INTERFACE_PROPOSAL, независимый review NOT_RUN.** Термины и
guards согласованы внутри пакета с ранними CYC-08/09, а не одобрены за R2/R3.
Реальная физика/параметры UNKNOWN. Это спецификация следующей модели, не
реализация новых CREATE/SPLIT/REMOVE в существующем движке. Расчёты и CAD не меняются.

## Граница и единый словарь

Материальная сущность `entity_id` обозначает конкретное множество вещества,
а не имя box в CAD. Одна сущность имеет `lineage`, `dose_ids`, `material_state`,
`mass_record`, `geometry_ref`, `location`, `custody`, `history`, `evidence`.
Положение, степень уплотнения, квалификация продукта и принадлежность учёта —
разные поля. Возвращённый пуансон не меняет ни одно из них автоматически.

| Поле | Определение / правило |
|---|---|
| `entity_id`, `event_id`, `batch_id`, `cycle_epoch` | Постоянные уникальные идентификаторы, времена/порядок и актуальность подтверждения. Дубликат события не добавляет/не списывает массу повторно. |
| `lineage`, `dose_ids` | Откуда пришло вещество, какие порции входят в batch/столб/сегмент. Слияние не создаёт дополнительную массу; partition должен быть полным и непересекающимся. |
| `material_state` | RAW, GATHERED_PARTIAL, COMPACTED_CANDIDATE, RETAINED_COLUMN, OUTGOING_SEGMENT и т.п. State label не подтверждает реальные плотность/качество. |
| `qualification` | NOT_ASSESSED / UNKNOWN / ASSUMED_CRITERIA_MET / VERIFIED отдельно. В этой редакции VERIFIED для REV не устанавливается. |
| `mass_record` | Значение/символ, единица kg, `basis_id`, влажностная база, uncertainty, source, status. Неизвестная масса — null с причиной; не исчезает из учёта. |
| `geometry_ref`, `location` | UNLOCATED / IN_PRESS / STRADDLING_EXIT / OUTSIDE_PENDING_RECEIPT / RECEIVER_DOMAIN / REMOVED_FROM_GEOMETRY. Геометрия может быть UNKNOWN. Выход передней грани не доказывает выход всего сегмента. |
| `custody` | UPSTREAM, PRESS_ACCOUNT, RECEIVER_ACCOUNT, DECLARED_LOSS_ACCOUNT. Только подтверждённая передача меняет сторону учёта. |
| `retained_inventory` | Столб A и допустимые остатки B — идентифицированная часть вещества, не произвольная числовая поправка. Остаток с неизвестной массой тоже сохраняется. |

`PRESS_DOMAIN` — область камеры/канала с выбранной плоскостью выхода;
`RECEIVER_DOMAIN` — отдельно определённая область приёмника. Их реальные
положения/ёмкость/интерфейсы UNKNOWN (Q-R3-03). Контракт не выбирает старую
R3-плоскость вместо CAD-плоскости и не назначает новый ход; это вход CYC-06.
`MODEL_DOMAIN` — область, где вещество способно влиять на модель/соседние движения;
она может включать приёмник. Выйти из PRESS_DOMAIN недостаточно для удаления тела.

## Одна массовая база и неизменяемый журнал

**L1 — выбор базы.** `basis_id` должен определять состояние измерения, влажность,
единицу и контрольную границу. Какой именно wet/dry basis нужен REV — UNKNOWN
(Q-R2-01). Все члены одного равенства имеют одну базу. Если влажность меняется,
отдельно учитываются сухое вещество, вода/пар и обмен через границу; переход
между базами требует исходных данных, не молчаливой конверсии.

**L2 — учёт по ответственности.** Для интервала между согласованными inventory-audit:

`M_press,end = M_press,start + Σ M_delivered − Σ M_accepted − M_declared_loss + M_exchange`.

`M_receiver,end = M_receiver,start + Σ M_accepted − M_receiver_onward`.

Все символы на L1. Это определения журнала, не новый расчёт или равенство
чисел с неизвестными. `M_press` означает ответственность PRESS_ACCOUNT,
включая не принятый материал за выходом. Pending receipt — **подмножество**
этого запаса, не дополнительный слагаемый. Геометрическая масса внутри камеры
не тождественна `M_press`; при straddling её доли могут быть UNKNOWN.
Ни потери, ни обмен, ни изменение остатков не предполагаются нулевыми.

**L3 — внутреннее преобразование.** Gather/уплотнение/изменение плотности/выделение
логического сегмента сохраняют состав вещества и lineage. Parent перестаёт
учитываться как отдельный активный запас при исчерпывающем partition детей;
архивная ссылка parent не суммируется ещё раз. При частичном partition оставшаяся
часть — явный child/remainder. Неизвестный partition запрещает его трактовку
как доказанный SPLIT. Граница логического сегмента не доказывает физический рез.

**L4 — передача.** Пересечение выхода меняет location. ACK_RECEIPT переводит ровно
одно согласованное множество вещества из PRESS_ACCOUNT в RECEIVER_ACCOUNT и
записывается обеими сторонами с одним transfer_id. Для частичной поставки
нужны отдельный идентифицированный сегмент и его масса/база; нельзя передать весь
parent по факту выхода его части. До ACK материал остаётся в PRESS_ACCOUNT.

**L5 — удаление геометрии.** REMOVE_GEOMETRY после разрешённых условий гасит лишь
геометрическое представление; entity и масса остаются в RECEIVER_ACCOUNT/архиве
журнала. Если приёмник входит в MODEL_DOMAIN либо тело ещё влияет на swept path,
удаление не разрешено. Нельзя сначала удалить тело, а затем получить PRODUCT_CLEAR
от его отсутствия. Вывод массы из дальнейшего учёта — отдельная последующая
передача/обоснованный поток, не побочный эффект REMOVE.

Загрузочная плотность относится к занятому объёму, плотность уплотнённого
вещества — к другому состоянию. `phi`/свободный объём камеры и занятый объём
различаются. Нельзя умножать уже усреднённую по камере плотность на phi повторно.
Новые значения rho/phi/влажности/потерь здесь не назначены (Q-R2-01/02/05).

## A: пуск, столб и установившийся режим

| Состояние | Содержимое и обязательное различие |
|---|---|
| A_UNKNOWN | Запас/история неизвестны. Нет права объявить пустоту, готовый столб или готовое изделие. |
| A_EMPTY | Подтверждённая в условном примере пустота. Это отдельный initial-state case, не результат одного HOME/уровня. Готового продукта нет. |
| A_STARTUP_RAW | Фактически доставленная сырая порция и сохранённые дозовые ID. Она ещё не готовое изделие/столб. |
| A_COLUMN_BUILDING | Материал накапливается/частично уплотняется по выбранной гипотезе пуска; неизвестны реальная реакция, удержание, достижение критерия столба. |
| A_COLUMN_ESTABLISHED | Критерии геометрии/истории/устойчивости удерживаемого столба заданы и приняты как гипотеза конкретного примера. Реальная возможность не подтверждена. |
| A_STEADY_LOADED | К известному retained inventory добавлена новая доставленная доза, не новый готовый product. |
| A_COMPACTED_CANDIDATE | После COMPACT та же масса имеет условно подтверждённую историю преобразования; outgoing/retained partition ещё требуется. |
| A_SEGMENT_READY | После заданного преобразования выделен выходящий участок с lineage/массой/базой и непересекающимся retained remainder. |
| A_EXITING | Участок движется/пересекает границу; до выхода всего выбранного участка и приёма масса не списывается. |
| A_OUTSIDE_PENDING | Выбранный участок целиком за выбранной границей, но подтверждённого приёма ещё нет. |
| A_RECEIVED_RETAINED | Участок принят/учтён приёмником, столб и остаток сохранены в PRESS_ACCOUNT. READY проверяется отдельно. |

**Гипотеза H-A:** исследуется раздельный пуск пустого канала и режим с retained
column. Конкретная пробка/запирающее устройство/материальный закон не выбраны.
`A_REACTION_DEFINED`, критерий образования/удержания столба и порядок пуска
UNKNOWN до Q-R2-03/Q-R3-02. Нельзя объявить любой возможный пуск невозможным
из-за отсутствия найденной процедуры аналога; нельзя и начать с готового product.

При пуске изменение retained inventory учитывается явно; `ΔM_retained = 0` не
полагается. Утверждение «нет квалифицированного продукта до критерия столба» —
ограничение H-A, не эмпирический факт об отсутствии любого истечения: возможный
неквалифицированный выход/потери остаются UNKNOWN и требуют отдельного учёта.
Повторные порции пополняют тот же lineage/journal; их количество и критерий
завершения пуска UNKNOWN. H-A не определяет реакцию или новое устройство.

В стационарном исследовании постоянство retained mass — **отдельная H-A-STEADY**,
не следствие слова STEADY и не правило для пуска. В общем случае L2/L3 сохраняют
изменение остатка/потерь/влаги. Равенство дозы и выходящего сегмента допустимо
лишь при всех соответствующих допущениях; нулевая разность остатков сама по себе
не доказывает их величину/геометрию/удержание. Выходящему сегменту не требуется
автоматически пройти весь канал одной новой дозой — CYC-06 получает сегмент,
границу и receiver после этого контракта, без автоматического удлинения хода.

## B: набор, продукт, выдача, остатки

| Состояние | Содержимое и обязательное различие |
|---|---|
| B_UNKNOWN | Инвентарь/остатки/история неопределены; пустой камерой не считаются. |
| B_ACCEPTABLE_INITIAL | Empty case либо явно выбранный допустимый остаток, проверенный по собственной политике. Не обязательно нулевая масса. |
| B_RAW_LOADED | Доставленная порция плюс идентифицированный допустимый остаток. |
| B_GATHERED_PARTIAL | Промежуточное состояние набора/предуплотнения; не квалифицированный готовый продукт. |
| B_BATCH_SELECTED | Решение завершить набор по определённым критериям; геометрия/масса/история batch прослеживаются. |
| B_COMPACTED | Преобразование завершено по критериям гипотезы; создан product candidate из того же вещества, не из пустоты. |
| B_EJECTABLE | Дополнительно выполнена условная цепочка разгрузки/отпирания/открытия; состояние материала не доказывает эти машинные условия. |
| B_EXITING | Выдача, возможен straddling; окончание хода не равно приёму. |
| B_OUTSIDE_PENDING | Весь выбранный product за выбранной границей, ACK отсутствует. |
| B_RECEIVED_RESIDUAL | Продукт принят, остатки в камере/на оснастке идентифицированы, их допустимость может быть UNKNOWN. |

**H-B-SINGLE/H-B-REPEAT** — две альтернативы одной схемы. SINGLE фиксирует одну
дозу только как сценарное условие. REPEAT допускает новые порции после partial
gather при безопасных для refill позах/удержании и доступной вместимости;
число наборов/критерии давления/позиции/массы UNKNOWN (Q-R2-04/Q-R3-02).
Источник ARS не даёт количественного правила REV. Сумма всех доставленных доз,
начальный/конечный остаток, обмен/потери и масса продукта связаны через L1–L4,
а не принудительным «одна доза = один брикет».

COMPACT — отдельное событие после набора/отсечения/допустимого состояния привода.
Если физический критерий неизвестен, реальный статус уплотнения/продукта UNKNOWN;
положительный пример использует только явно ASSUMED критерий. Завершение таймера,
достижение одной координаты либо заранее нарисованный box не создают продукт.

B_EJECTABLE требует UNLOADED → LOCK_CLEAR → STOP_OPEN с валидными основаниями.
Действительная остаточная реакция/энергия и пороги UNKNOWN; физическое открытие B
INDETERMINATE. После приёма/возврата RESET stop/lock требует проверки sweep по
продукту **и остаткам**; ACK_RECEIPT не гарантирует PRODUCT_CLEAR для закрытия.
Проверенный empty/allowed-residue case для следующего batch восстанавливается
только отдельным inventory/ready audit, не автоматическим удалением вещества.

## События, доказательства и результат перехода

contract.json задаёт state IDs, event IDs, guards и переходы; events.md —
значение события и последствия L1–L5. Точка времени/номер команды — locator,
не подтверждение состояния. Нужны ID/epoch, полный объект/участок, актуальное
основание и обратная связь. Устаревшее/дублированное/противоречивое подтверждение
не используется повторно.

Результаты документа: `ALLOWED_ASSUMED` при всех TRUE в явно условном примере;
`INDETERMINATE` при неизвестном обязательном условии без известного нарушения;
`BLOCKED` при известном FALSE/неверном исходном состоянии/нарушении журнала,
даже если другое условие UNKNOWN. Ни один результат не является физическим
разрешением или доказательством контроллера. Проверка логической полноты
примеров не проверяет материальный закон, массы, геометрию или датчики.
