# Символические примеры материального журнала

Все выражения на **одной заранее определённой базе S** (L1). S для REV UNKNOWN,
массы/потери/обмен/влажность UNKNOWN, численного расчёта нет. Индексы обозначают
сущности/интервалы, не новые параметры изделия. Равенства — требования к будущему
журналу, не результат измерений. Материальное состояние не выводится из равенства.

## A: пуск и начало установившегося исследования

Пусть D_start,i — действительно доставленные сырые порции пуска, C_start —
идентифицированное вещество создаваемого столба, U_start — прочий ещё не принятый
материал под ответственностью пресса (включая возможное неквалифицированное
истечение), T_start — принятый поток, L_start — объявленные потери, X_start —
знаковый обмен. Тогда:

`M_press,start + Σ M(D_start,i) + X_start = M(C_start) + M(U_start) + T_start + L_start`.

Исходная пустота допускается только в явно проверенном empty case. До
ESTABLISH_COLUMN/COMPACT/partition нет квалифицированного S_out. Возможные
истечение/потери не объявляются отсутствующими. При неизвестной реакции или
массовой базе критерий столба INDETERMINATE, накопленное вещество остаётся в учёте.
Факт доставки очередной дозы не создаёт дополнительно массу столба.

После column audit для одного steady-интервала перед приёмом S_out:

`M(C_before) + M(D_next) + M(U_before) + X = M(C_after) + M(S_out_pending) + M(U_after) + T_other + L`.

Здесь C_after и S_out_pending — непересекающиеся части вещества. Пока нет ACK,
S_out_pending входит в PRESS_ACCOUNT вместе с C_after и U_after; parent не
прибавляется к детям. Нельзя объявить M(C_before)=M(C_after) только из STEADY;
это отдельная H-A-STEADY. Нельзя вывести массу нового сегмента только из
новой дозы без остатков/потерь/обмена. Плотность raw не задаёт длину сегмента
после уплотнения без материальных данных.

ACK переводит **именно S_out** в RECEIVER_ACCOUNT с тем же transfer_id/базой;
C_after и U_after не удаляются. Если требуются частичные приёмы, нужны отдельные
segment_id с непересекающимся partition и своим основанием массы. Если граница
сегмента не установлена, передача INDETERMINATE, не принудительный SPLIT.

## B: single либо repeated gather

R_before — допустимый идентифицированный начальный остаток; D_batch,i — каждая
доставленная порция одного выбранного batch. После gather новых продуктов не
возникает. После SELECT_BATCH/COMPACT и явного partition:

`M(R_before) + Σ M(D_batch,i) + X = M(P_candidate) + M(R_after) + M(U_after) + T_other + L`.

В SINGLE множество D_batch содержит единственную сценарную порцию; в REPEAT
оно включает все повторные доставки. Ни одна из гипотез не устанавливает
количество доз REV. P_candidate — то же вещество после преобразования, не
прибавляемый к старому batch второй запас. Его квалификация/свойства остаются
UNKNOWN вне явно ASSUMED примера. R_after сохраняется даже при неизвестной массе.

Выдача меняет положение P_candidate, пересечение выхода — location, ACK —
сторону учёта. До ACK продукт целиком остаётся в PRESS_ACCOUNT. После ACK
P_received учтён в RECEIVER_ACCOUNT, но может всё ещё пересекать reset sweep.
Поэтому `RECEIPT_VALID=TRUE` и `RESET_SWEEP_CLEAR=FALSE` совместимы: RESET BLOCKED.
RETURN_TOOLS и REMOVE_GEOMETRY не меняют ни одной массы этих уравнений.

## Обязательная запись будущего интерфейса

Каждая material/mass запись содержит `entity_id`, `basis_id`, `value` (null при
UNKNOWN), `unit`, `status`, `unknown_reason`, `uncertainty`, `source` и epoch.
Поток exchange имеет определённый знак; loss — свой идентифицированный account.
Перевод между влажностными базами требует отдельных водных/сухих составляющих
и исходных данных. Допуски/неопределённости не назначены нулями. Невязка или
неизвестный поток не заполняются «нужной» массой остатка для получения READY.

Массовая запись при ACK связывает обе стороны, а не удаляется после моделируемого
REMOVE. Повтор ACK — ссылка на существующий transfer либо ошибка; второй перенос
недопустим. Ни неизвестный CREATE/SPLIT, ни неопределённый receiver не отменяют
уже доказанного исчезновения/двойного учёта вещества (BLOCKED имеет приоритет).
