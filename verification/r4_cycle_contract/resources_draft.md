# CYC-08 — ранний событийный и ресурсный контракт

Уточнение редакции 2: RESOURCES_READY относится к текущему выбранному действию
и всем его обязательным потребителям. Доступность ресурса — entry каждого
движения, включая startup/refill/возврат/reset; NONE/UNKNOWN не разрешают действие.
Изменение любого обязательного потребителя инвалидирует прежнее доказательство.
Паузы/восстановление не получают общий READY по умолчанию; permissions.md задаёт
собственные условия восстановительных запросов. Численный слой ниже неизменён.

**ASSUMED_INTERFACE_PROPOSAL, не окончательная циклограмма.** Связь с CYC-01:
события/материал в contract.json; все исходные строки A0…A8/B0…B8, включая
B4U/B4O, подробно связаны в resources.json и traceability.json. Все количественные
слоты `value: null`, `status: UNKNOWN`, с единицей и причиной. Значения R3 не
пересчитываются/не перезаписываются; новые времена и производительность не выданы.

## Порядок стадий и ветвления

| Вариант | Каркас порядка; стрелка — зависимость, не доказанная длительность |
|---|---|
| A startup H-A | audit → доставленная доза → отсечение → подход/partial gather → проверка столба; при незавершённом столбе — восстановление refill позы/удержания → следующая доза → повтор. Условия реакции/критерий столба UNKNOWN. Неквалифицированное истечение/потери должны оставаться в журнале. |
| A steady H-A | retained audit → доза → отсечение → подход/COMPACT → удержание/требуемая разгрузка с сохранением столба → partition outgoing/retained → выдача → полный выход → ACK → возврат/удержание → reconcile → target READY. Взаимное перекрытие сжатия/вытеснения не определено; граф не требует автоматически отдельного длинного хода через весь канал. |
| B single/repeat | audit → доза → отсечение → подход/partial gather; если refill допустим — восстановление позы/вместимости → доза снова; SELECT_BATCH → главное сжатие → hold → подтверждённая разгрузка → отпирание → открытие → выдача → полный выход → ACK → возврат → product/residue sweep clear → reset stop/lock → inventory reconcile → target READY. |

У B разгрузка, отпирание и открытие — отдельные последовательные подтверждения.
`B-OPEN-CONFIRM` только читает историю B4 → B4U → B4O; он не исполняет три движения
одновременно. Обратное восстановление требует собственной определённой R3
последовательности/проверки, а не автоматического обращения стрелок. Реальное
открытие B INDETERMINATE. Подача не идёт через закрытое отсечение; для каждого
refill требуются заново разрешённые поза, вместимость и актуальный feedback.

Дополнительные обязательные интервалы, не потерянные между строками: подготовка
порции снаружи и её реальная передача; ожидание приёмника/приёма; восстановление
подачи и готовности ресурсов; standby/паузы; останов, сохранение остатка/состояний,
диагностика и повторный audit при возобновлении. Применимость их приводов/условий,
время и мощность UNKNOWN. Останов не стирает inventory/epoch и не запускает
повторную доставку/списание старого события. REMOVE_GEOMETRY — условная операция
модели после L5, не обязательная физическая стадия потребления энергии.

## Потребители и интервальные величины

Для **каждого** event interval/ветви будущий ответ R3 должен дать начало/конец,
условие завершения, предшественников, привод, feedback и применимость. Ресурсные
строки A8/B8 покрывают стадии, а не добавляют последовательное время поверх них.

| Потребитель | Что требуется; сейчас UNKNOWN |
|---|---|
| Приём/дозатор/подача | Двигатель/шнек/мешалка, если существуют; накопление порции, реальный ввод, паузы/отсечение. Транспорт и буфер не назначены. |
| Главная ось | Подход, gather, сжатие, hold, разгрузка, выдача при применимости, возврат; давление/расход обеих полостей и времени каждой операции. |
| Отсекатель, A clamp/удержание | Перемещение и удержание, утечки/подпитка, реакция при возврате. Не считать статическую силу бесплатным удержанием. |
| B замок/упор | Отдельные unload, unlock, open и восстановление, общая/раздельная гидравлика UNKNOWN. |
| Выдача/приёмник | Возможные собственные приводы/транспорт, доступная ёмкость, ожидание и приём UNKNOWN; механизм не выбран. |
| Гидростанция | Насос/мотор, supply и слив, регулирование/байпас, клапаны, утечки, накопители при наличии, КПД/потери и одновременные ветви UNKNOWN. COTS не определяются по одной мощности. |
| Вспомогательные | Охлаждение, смазка, управление, датчики, питание клапанов/standby, пуск/останов и fault/recovery — состав/применимость/энергия UNKNOWN. |

Раздельно требуются `p_supply`, `p_port_in`, `p_port_out` с определением
absolute/gauge, `Q_in` и `Q_out` с направлениями и полостью: площади могут
различаться, поэтому равенство расходов не предполагается. Нужны ветвление,
совместная работа, слив/противодавление, потери/регулирование и электрическая
мощность на выбранной границе. Сумма сил×скоростей не равна автоматически
электрическому потреблению. Hold/standby/ожидание не получают нулевую мощность
из нулевой скорости. `NOT_APPLICABLE` требует отдельного основания применимости;
подтверждённый ноль — численное доказательство, а UNKNOWN — не любой из них.

Время полного цикла относится к повторению **одного mode/READY target** вместе с
материалом и всеми обязательными интервалами. Пуск A и B single/repeat могут
иметь разные границы цикла. Старый main-axis fixed-budget интервал/ограничение
и CAD diagnostic duration остаются данными своей области. Они не определяют
полный цикл, производительность, установленную мощность или ресурсную
достаточность. Fixed-times — отдельная неутверждённая постановка. Итоговые
интегралы энергии/критический путь здесь не вычисляются: граф и входы неполны.

## Возможные перекрытия — только вопросы

| Кандидат | Условие до разрешения, сейчас UNKNOWN |
|---|---|
| Внешняя подготовка следующей порции с прессованием | Независимые объём/ресурс, отсутствие передачи в закрытый тракт, сохранённая идентичность дозы, ёмкость/порядок. |
| Возврат оси с приёмом сегмента | Выходящий материал/остаток не попадают в sweep; подтверждены непрерывность, удержание A и независимый ресурс. Pending receipt остаётся PRESS_ACCOUNT. |
| Несколько гидравлических движений | Пропускная способность/давление/регулирование обеих ветвей, приоритеты и обратные потоки, отсутствие конфликта движений. |
| Охлаждение/контроль со стадиями | Возможная постоянная работа с отдельным учётом энергии, без двойного суммирования наложенных интервалов. |

Ни одно перекрытие не разрешено этой таблицей. PRODECO/другие аналоги дают
источник гипотезы, не расписание REV. Q-R3-04/05 остаются AWAITING_RESPONSE;
окончательный CYC-08 — после CYC-02…07 и ответов, по отдельному scope.
